# Strategy & Plan stage (D3 and D4 only)

This stage runs after the Unified Recommendation is drafted and before the Independent Review.

- **Who:** the Engagement Manager leads, with the experts. The Quant Analyst builds the budget ranges and KPI baselines in code, from the same model used for the scenarios.
- **When it runs:** only when the verdict is go or conditional go.
- **When it does not:** if the verdict is "buy information first", the plan is the test plan (`deliverables-and-monitoring.md` §3), not a launch plan. Say so in one line.

## Part A: Strategy (D3, D4)
1. **Posture**: choose / sharpen / execute / correct, from the starting point in Stage 1.
2. **Diagnosis**: the 3–5 evidence-backed truths that must shape the choices, from the ledger only.
3. **Choices**:
   - Where to play: segments, geographies, channels.
   - How to win: the advantage, and why it is hard to copy.
   - Participation model: alone, with a partner, or by acquisition.
4. **Not doing**: explicit exclusions and what will stop. A strategy with no exclusions is a wish list.
5. **Coherence test**: do the choices reinforce each other? Name any pair that conflicts and how it is resolved.
6. **Objectives**: outcome statements, each with at least one KPI card.
7. **Capabilities**: people, data, technology, partners and governance that must exist. Each is linked to a choice; capabilities not linked to a choice are cut.
8. **The logic in one sentence**: "لأن [التشخيص]، نختار [الخيارات]، عبر [القدرات والمبادرات]، ونقيس النجاح بـ[المؤشرات]."

## KPI card
| Field | Content |
|---|---|
| Name | Short and specific |
| Definition | What counts and what does not |
| Formula | Written out |
| Data source | Where the number comes from |
| Baseline | Value and date, or "لا يوجد خط أساس" plus how to set one |
| Target | Value and its origin: the user, derived from their numbers, a linked benchmark, or "هدف داخلي مقترح" |
| Owner | The role that controls the driver, not only the one that reports it |
| Cadence | How often it is reviewed |
| Type | Leading or lagging |

Arrange the KPIs as a tree: outcome → drivers → leading indicators. Every leaf has an owner.

## Part B: Plan (D3, D4)

### Initiative card
| Field | Content |
|---|---|
| Name | |
| Objective served | Which strategic objective |
| Mechanism | How it produces the effect |
| Owner and authority | Role, and who must approve it |
| Deliverables | Concrete outputs |
| Budget | Low / base / high, split into one-off and recurring, with the basis (a quote, a linked benchmark, or an estimate labelled تقدير) |
| Resources | People, skills, data, technology, partners |
| Dependencies | Typed (see Part C) |
| KPIs | KPI cards |
| Risks | With mitigations |
| Stop / scale rule | The result that triggers a stop, and the result that triggers scaling up |

### Portfolio check
- **Coverage:** every objective has at least one initiative.
- **Overlap:** two initiatives doing the same work.
- **Conflict:** competition for the same people or budget.
- **Missing enablers:** data, hiring, legal or procurement work that no initiative covers.

### Governance
State who decides what (decision rights), the review cadence and the escalation route. For a small team, a simple table is enough: decision | who decides | who is consulted | who is informed.

### Budget summary
The total is a range: the sum of the low, base and high estimates of each initiative, with one-off and recurring shown separately. Show the build-up in a waterfall chart or table generated by code.

## Part C: Sequence (D4 only)
- Type every dependency:
  - **hard**: cannot start before the other finishes;
  - **soft**;
  - **resource**;
  - **information**;
  - **regulatory**;
  - **decision**.
- Find cycles and the critical path.
- Give each phase one objective, an entry gate and an exit gate, and state what goes wrong if the gate is skipped.
- Use duration ranges, not single dates. Give dates only when durations and dependencies support them.
- Draw the phases as a simple diagram generated by code; a Mermaid gantt is acceptable.

## Rejected if
- The strategy is a list of initiatives rather than a set of choices, or has no exclusions.
- It restates the current direction without naming the next open choice or the execution gap.
- An initiative has no card, or a KPI has no card.
- The budget is a single number, has no basis, or does not separate one-off from recurring costs.
- Milestones are dates without deliverables or gates.
- Dependencies are untyped (D4), or a phase has no objective or gate.
- A step lies outside the owner's authority and no approver is named.
